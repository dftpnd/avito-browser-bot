# Avito Browser Bot

Локальный помощник по покупке на Rust: задачи с изменяемыми требованиями, архив переписок в SQLite, анализ условий DeepSeek, кнопки статистики в Telegram и события совпадений. Авито используется через уже авторизованный Chromium.

Реализованные возможности и текущие ограничения перечислены в [docs/implementation-status.md](docs/implementation-status.md). Полный следующий сценарий описан в [плане](docs/purchase-assistant-plan.md).

## Браузер

Использовать **Snap Chromium** `/snap/bin/chromium`, профиль `/home/mg/kinobot/chrome-profile`, CDP `http://127.0.0.1:9222`. Сначала использовать работающий экземпляр. Бот проверяет параметры процесса и создаёт свою вкладку, которую закрывает при обычном завершении. Пользовательские вкладки и браузер не закрывает.

`/home/mg/kinobot` — отдельный проект. Здесь используется только уже авторизованная сессия Chromium с профилем по указанному пути. Проект Авито находится в `/home/mg/projects/avito`.

Если браузер ещё не запущен:

```sh
/snap/bin/chromium \
  --user-data-dir=/home/mg/kinobot/chrome-profile \
  --remote-debugging-address=127.0.0.1 \
  --remote-debugging-port=9222 \
  about:blank
```

Не запускать другой профиль и не перезапускать работающий браузер. Если нужен вход или проверка Авито, пройти её вручную. Бот не копирует профиль и cookies. При ошибке, капче или неожиданном перенаправлении текущий сбор останавливается без записи успешного сканирования.

## Запуск

Нужны Rust с поддержкой edition 2024 и работающий Chromium. Сборка SQLite включена в зависимости.

```sh
cargo build --release --locked
# Разовый сбор до трёх страниц готового поиска:
cargo run --release -- scan 'https://www.avito.ru/moskva?q=steam+deck' --pages 3
# Мониторинг каждые пять минут:
cargo run --release -- watch 'https://www.avito.ru/moskva?q=steam+deck' --pages 3 --interval 300
# Просмотр базы без подключения к браузеру:
cargo run --release -- list
cargo run --release -- report --output data/report.html
```

Поиск в примерах иллюстративный. Подставить свою ссылку. Параметры ссылки сохраняются, `p` заменяется номером страницы. Между страницами CLI пауза 20 секунд; минимальный интервал мониторинга Telegram — 1800 секунд после завершения прохода. Первый проход помечает все впервые увиденные в этом поиске объявления как новые. Повторные проходы возвращают только новые объявления и изменения цены в `changes`; строка JSON в stdout содержит также число просмотренных объявлений. Остановка — Ctrl+C, текущий проход завершается перед выходом.

База по умолчанию — `data/listings.sqlite`. Можно выбрать другую: `cargo run -- --database data/other.sqlite scan 'https://www.avito.ru/moskva?q=example'`. После успешного сканирования рядом с базой создаётся `report.html`. История изменений хранится в таблице `changes`, история проходов — в `scans`. Отчёт содержит все когда-либо сохранённые объявления; их актуальность на площадке не гарантируется. Исчезновение из выдачи не считается удалением.

Сбор ограничен указанным числом страниц. Бот читает только карточки поисковой выдачи, не открывает подробные страницы объявлений. Разметка Авито может измениться; её проверка на настоящем поиске нужна при первом запуске. Скорость появления в выдаче и доставки уведомлений Авито не гарантируется. Дополнительные фильтры — следующий этап. Telegram-команды и уведомления описаны ниже.

## Telegram

Бот [@dft_avito_bot](https://t.me/dft_avito_bot) управляет сканированием и отправляет изменения владельцу. Используется [Telegram Bot API](https://core.telegram.org/bots/api) с long polling; публичный HTTP-сервер не нужен. Разрешён только личный чат с проверенным `owner_id`, сообщения остальных отправителей игнорируются без ответа. Токен не логируется.

Локальный файл `config.local.json` исключён из Git и должен иметь права `600`:

```json
{
  "token": "BOT_TOKEN_FROM_BOTFATHER",
  "owner_id": 123456789
}
```

`owner_id` — реальный числовой ID владельца, не username. Сначала отправить `/start` боту, выполнить `cargo run -- telegram-setup`, проверить, что показанный ID принадлежит вам, и записать его в локальный конфиг. Команда настройки только читает входящие сообщения, не отвечает и не назначает первого обратившегося владельцем. При `owner_id: null` рабочий режим не запускается.

```sh
cargo run --locked -- telegram-setup
cargo run --locked -- telegram
```

Команды в личном чате:

- `/start`, `/help` — помощь.
- `/scan ССЫЛКА [страницы]` — один проход.
- `/watch ССЫЛКА [интервал_сек] [страницы]` — включить или заменить один наблюдаемый поиск.
- `/stop` — остановить мониторинг.
- `/status` — показать состояние.

В Telegram по умолчанию — одна страница и 1800 секунд; максимум 10 страниц, интервал от 1800 до 86400 секунд. Собственные фильтры не добавлены: используется готовая ссылка поиска. Команды обрабатываются последовательно. Во время прохода ответ на `/stop` откладывается до его завершения; при ожидании Telegram — до 20 секунд. При ошибке сбора мониторинг отключается, после устранения причины его нужно включить командой `/watch`.

Состояние мониторинга, offset входящих команд и отметка доставки сохраняются в SQLite. Бот отправляет все новые события базы, включая события от CLI после первоначального запуска Telegram-режима. Старую историю до первого запуска не рассылает. Неудачная отправка объявления повторяется; при сбое между отправкой и подтверждением возможен дубль. Ошибка разбора команды или сбора отвечает отдельным сообщением, для этих служебных ответов нет отдельной очереди доставки.

Бот запускается без браузера; подключение к Chromium происходит при первом сканировании. Остановка процесса сохраняет подписку для следующего запуска; `/stop` отключает её в базе. Один экземпляр Telegram-режима на одну базу и один токен. Webhook и long polling одновременно не используются; существующий webhook автоматически не удаляется.

Для фонового запуска на этой машине после настройки владельца:

```sh
cargo build --release --locked
mkdir -p ~/.config/systemd/user
cp deploy/avito-telegram.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now avito-telegram.service
journalctl --user -u avito-telegram.service -f
```

Unit рассчитан на каталог `~/projects/avito` и пользовательскую сессию systemd. Для сканирования нужен работающий Chromium с указанным выше профилем. Конфиг и базу в репозиторий не добавлять; после смены токена обновить локальный файл и перезапустить сервис.

## Покупка и статистика

Кнопки: «Сводка», «Подходят», «Лучшие», «Диалоги», «Цены», «Работа бота», «Изменения», «Требования», «Пауза». Они читают локальную БД, без новых запросов к Авито. В архиве учитывается весь аккаунт, оценки и совпадения относятся к текущей задаче и версии требований.

- `/requirements` — показать условия покупки.
- `/task текст` — подготовить изменённые требования обычным текстом через DeepSeek.
- `/approve` — подтвердить показанный черновик.
- `/card ID` — сохранить описание уже найденного объявления (требует прямого маршрута).
- `/analyse ID` — извлечь факты и оценить по текущим условиям.
- `/link ID_объявления ID_диалога ID_продавца` — связать предложение с архивом; ID продавца нужно проверить, чтобы не принять сообщения покупателя за подтверждение.
- `/draft ID` — сохранить вопросы по оставшимся пробелам; эта команда не отправляет их продавцу.
- `/history ID_диалога [страница]` — посмотреть архив, скрывая данные доступа и контакты.
- `/trust ID_продавца` — отметить магазин проверенным владельцем на 30 дней.
- `/network` — показать причины сетевой паузы.

Начальная задача RTX PRO 6000 — черновик: 96 ГБ предполагаются, бюджет и допустимость Max-Q требуют уточнения. Работа с несколькими задачами пока не реализована. Последовательные уточнения подключены к очереди и по умолчанию выключены; ограничения и команды — в [docs/sync-and-outreach.md](docs/sync-and-outreach.md). Живой прогон требует подтверждённого прямого маршрута.

DeepSeek: локальный `config.local.deepseek.json` с полями `api_key`, `base_url` (`https://api.deepseek.com`), необязательным `model`; права 600, вне Git. При отсутствии model адаптер читает список доступных моделей. Лимит 30 попыток оценок/изменений требований за 24 часа, максимум 3000 выходных токенов на оценку и до 24000 символов входных источников. Повторная оценка неизменных данных использует кэш. Для неудачного ответа usage может быть неизвестен; попытка всё равно учитывается. Денежный лимит по актуальным тарифам пока не реализован.

Полное совпадение требует текущих подтверждений всех обязательных условий. Факты подтверждаются точными цитатами из источников; источником подтверждения продавца может быть только сообщение связанного продавца. Входящие данные предварительно очищаются от распознанных контактов и данных доступа. Эта очистка ограничена эвристиками и не является гарантией обнаружения любых секретов. Модель не подтверждает магазин и не отправляет сообщения.

При переходе в полное совпадение или выходе из него событие и оценка сохраняются одной транзакцией. Уведомления доставляются владельцу с повтором при сбое. Прочитанное сообщение Telegram и доставленное сообщение пока не различаются; повторная доставка после аварии между send и отметкой в БД возможна.

## Архив и резервные копии

```sh
cargo run --locked -- import-chats avito-export/all-chats.json
cargo run --locked -- backup data/backup.sqlite
cargo run --locked -- network-check
```

Импорт сохраняет исходные каналы и сообщения, наблюдаемые правки и метаданные вложений, не меняя JSON-снимки. Повторный импорт не создаёт дубли. Команда `/attachments` добавляет доступные файлы в очередь; приватные и устаревшие ссылки могут остаться недоступными. Живая синхронизация подключена к очереди через `/sync`, но до проверки прямого маршрута локальный архив остаётся снимком на исходную дату. Проверка резервной копии включает SQLite integrity_check.

Весь сетевой доступ адаптера Авито проверяется перед навигацией. Текущая консервативная проверка отклоняет proxy-переменные, нестандартную policy routing и отсутствие обычного физического маршрута. Она намеренно не делает исключений по предположению. Настройку системного VPN нужно проверить отдельно с администратором; один `no_proxy` не обходит прозрачный перехват. Пока маршрут не подтверждён, сбор карточек и выдачи закрыт; локальные функции продолжают работать.

## Проверки

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
# Дополнительно: тест извлечения карточек в отдельной вкладке работающего Chromium:
cargo test --locked -- --ignored
```

Обычные тесты не требуют браузера или сети. Браузерный тест использует локальную HTML-фикстуру; объявления Авито не запрашивает.

## Устройство

Сценарии зависят от небольших интерфейсов `ListingSource` и `ListingRepository`. Домен проверяет объявления и ссылки. CDP, разметка Авито, SQLite и HTML изолированы в адаптерах. Подробности GRASP/SOLID и границы дальнейшего развития описаны в [docs/architecture.md](docs/architecture.md).

## Локальные данные

`data/`, выгрузки `avito-export*/`, архивы, личные настройки и профили исключены из Git. Исходные локальные инструкции и описание прежней выгрузки сохранены в `README.local.md`, этот файл не публикуется. Старые выгрузки и `export_avito.py` сохраняются на месте, бот их не изменяет.
