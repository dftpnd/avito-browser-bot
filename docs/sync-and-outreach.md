# Синхронизация и последовательные уточнения

Код следующего этапа подключён к Telegram-сервису. Живой прогон Авито пока заблокирован отсутствием подтверждённого прямого маршрута. Алгоритмы очереди, пагинации и отправки проверяются на искусственных данных; JavaScript проверки истории дополнительно проверен в отдельной пустой вкладке Chromium с подменённым локальным клиентом. Настоящим продавцам в ходе этих проверок сообщения не отправлялись.

## Команды

- `/research` — проход по запросам текущей задачи: до 10 страниц на запрос, затем новые/просроченные подробные карточки и анализ. Фактическая полнота ограничена этим лимитом.
- `/sync` — обновить список чатов аккаунта и поставить истории в очередь.
- `/sync ID_диалога` — приоритетная синхронизация выбранного диалога.
- `/queue` — прогресс, пауза, ожидание ответов и неопределённые отправки.
- `/outreach on` — разрешить автоматическую подготовку и последовательную отправку оставшихся уточнений после анализа. Требования должны быть подтверждены.
- `/outreach off` — прекратить автоматические уточнения и отменить ещё не начатые отправки/открытия диалогов; `/pause` также останавливает всю очередь.
- `/send ID_объявления` — поставить один актуальный черновик на отправку. Нужна свежая полная синхронизация связанного диалога и подтверждённая действующая задача.
- `/attachments` — поставить до 50 доступных ссылок вложений на загрузку.
- `/pause`, `/resume` — остановить/возобновить общую очередь. При возобновлении ошибки чтения можно повторить; неопределённые отправки автоматически не повторяются.
- `/dismiss_send ID_операции` — после ручной проверки снять неопределённую операцию с автоматики. Ничего не удаляет у продавца, не утверждает отсутствие сообщения и не повторяет его.

## Синхронизация

Все задания и контрольные точки хранятся в SQLite. Перед сетевым шагом проверяется доступ; затем в транзакции резервируется общий временной слот. Между стартами обычных шагов минимум 20 секунд. Для условной отправки (свежая история плюс одно сообщение) резервируется 45 секунд до следующего шага. Работа идёт последовательно в одном процессе. Telegram long polling может увеличить интервалы.

Чтение выполняет существующий авторизованный клиент страницы Авито с `cache:false`. Инициализация клиента зависит от внутренних модулей сайта и может потребовать ремонта при изменении сборки. Пользовательские вкладки не закрываются, исходные JSON-снимки не изменяются.

Первичная история постранично загружается до явного конца. Полная страница без флага окончания требует следующего запроса; повтор границы с полной страницей не объявляется успехом. При наличии полного сохранённого основания новая история читается до первого известного сообщения. Это сокращает повторный обход, но не обнаруживает правки старых сообщений за пределами обновлённого участка.

Связанные диалоги после `/sync` проверяются с предлагаемым интервалом 180 секунд через ту же очередь, поэтому фактический интервал может быть больше. После сохранения ответа создаётся анализ связанного предложения, затем переоцениваются совпадения. Изменившееся содержимое аннулирует старые черновики; отметки прочтения сами по себе не меняют ключ содержимого диалога.

Связь объявления определяется по ссылке/ID предмета диалога. Собеседник назначается продавцом автоматически только когда текущий аккаунт однозначно сопоставлен одному участнику и остаётся ровно один другой. При неоднозначности требуется `/link`; неизвестный отправитель не получает статус подтверждения продавца.

## Отправка

По умолчанию автоматические уточнения отключены. После включения и подтверждения задачи анализ может открыть диалог по объявлению через штатный метод клиента, сначала загрузить историю, подготовить вопросы и поставить их в очередь. Создание диалога само по себе не отправляет текст.

Намерение отправки, точный текст и постоянный randomId записываются до обращения к Авито. Один незавершённый исходящий запрос на диалог; пока ждём ответ, следующий не ставится. В глобальном масштабе допускается только один writer; неопределённый результат блокирует новые отправки до сверки. Новые требования отменяют старые черновики и ожидающие отправки.

Перед фактической отправкой в странице выполняется свежий запрос истории и сравнение ID и стабильного содержимого с сохранённой первой страницей. Проверяются также изменения вложенных полей body. Если появилось ручное сообщение или ответ, отправки нет: данные сохраняются и назначается синхронизация. При неизменной истории выполняется ровно один вызов штатной функции отправки. Внешнее изменение между ответом сервера на проверку и принятием отправки остаётся возможной гонкой; атомарного серверного compare-and-send API здесь нет.

Ответ отправки сохраняется в архив. Тайм-аут или падение процесса переводит операцию в unknown. Сверка ищет её по randomId в свежей истории и восстанавливает подтверждение, если сообщение найдено. Отсутствие сообщения в одной странице не доказывает отсутствие отправки. Слепой повтор запрещён. Контроль ожидаемого ответа использует время подтверждённого исходящего сообщения, когда оно известно.

Если в диалоге слишком много текста для лимита контекста DeepSeek, анализ останавливается с видимой причиной, а не выкидывает старые вопросы незаметно. Компрессия и устойчивые сводки длинных диалогов пока не реализованы.

## Вложения

Скачиваются только HTTPS-ссылки доменов avito.ru, avito.st, avito.com и их поддоменов. Каждое перенаправление проверяется заново, прокси-переменные HTTP-клиент не использует. Нужен прямой маршрут. Лимит файла — 20 МБ; содержимое хранится как неисполняемый .bin с SHA-256 и метаданными в БД, каталог имеет права 700, файлы — 600. Файлы не запускаются и не публикуются.

Публичные доступные ссылки могут быть загружены. Приватная ссылка, требующая сессионного доступа, либо устаревший URL помечаются unavailable: cookies из браузера не извлекаются. HTML вместо файла и сетевые ограничения останавливают очередь. Поддержка приватных файлов через штатный клиент страницы требует отдельной проверки.
