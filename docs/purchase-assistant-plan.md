# Черновик плана: поиск, проверка и сравнение вариантов покупки

Статус: реализация начата; работающие функции и оставшиеся этапы перечислены в `docs/implementation-status.md`. Сценарий — покупка NVIDIA RTX PRO 6000 Blackwell, исключая Server Edition. Указанные пользователем 94 ГБ предположительно означают 96 ГБ; точную версию и допустимость Max-Q нужно подтвердить.

Источники: [семейство RTX PRO 6000 у NVIDIA](https://www.nvidia.com/en-sg/products/workstations/professional-desktop-gpus/rtx-pro-6000-family/), [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/).

## Цель и порядок предпочтений

Собрать максимально полную доступную выборку Авито по группе запросов, проверить предложение и условия у продавца, представить сравнение со ссылками и доказательствами. Абсолютную полноту всей площадки не гарантировать: показывать запросы, регионы, просмотренные страницы, дату сбора и незавершённые участки.

Предварительный порядок групп:

1. Подходящая карта физически в наличии с возможностью проверки и покупки.
2. Подходящая карта под заказ, продавец финансирует закупку, покупатель оплачивает при передаче.
3. Подходящая карта под заказ с предоплатой в пределах заданного лимита.

Для вариантов под заказ требование проверенного магазина пока предлагается применять ко всем группам; пользователь должен подтвердить границу. Неподтверждённые предложения остаются кандидатами и не смешиваются с подтверждёнными. В каждой группе учитывать итоговую цену, срок, гарантию, способ проверки и факты о продавце. Финансирование закупки отделить от оплаты перевозки.

## Динамические требования

Поиск становится отдельной задачей покупки с версионируемыми требованиями: товар, допустимые версии и состояние, исключения, город получения, бюджет, срок ожидания, предоплата, магазин, доставка, гарантия, необходимые подтверждения. Для каждого требования — обязательность, значение и приоритет.

Бот переводит текст пользователя в структурированную карточку требований и показывает её для проверки. Изменения требований пересчитывают локальную выборку без повторной загрузки сайта. Смена обязательных требований приостанавливает очередь исходящих уточнений до проверки новых вопросов. Историю предыдущих оценок и ответов сохранять.

## Сбор и покрытие

Группа запросов с вариантами написания RTX PRO 6000 / Blackwell / 96 GB; первоначальная область — вся Россия, город получения задаётся отдельно. Объявления разных запросов объединяются по ID. Одинаковый продавец с несколькими объявлениями получает одну связанную карточку и один диалог уточнения.

После выдачи открывать подробную карточку только нового или изменившегося кандидата. Сохранять описание, цену, версию, объём памяти, наличие, заявленный срок, оплату, гарантию, место и доступные сведения о магазине. Не превращать стоимость минимальной комплектации или предоплаты в итоговую цену товара. Отдельно распознавать комплекты с компьютером, услуги и похожие модели.

Для каждого поля хранить значение, источник, время, короткую подтверждающую цитату и статус: неизвестно / заявлено в объявлении / подтверждено продавцом / есть дополнительное доказательство / противоречие. Не считать слова продавца независимой проверкой.

## DeepSeek и ранжирование

DeepSeek извлекает поля из описания и объясняет соответствие требованиям. Вход — публичное описание и минимальные обезличенные фрагменты ответов, необходимые для оценки; не вся история переписки. Ключ хранится локально вне Git.

Выход модели проверяется по схеме: значение, неизвестные поля, противоречия, цитаты, уверенность и предлагаемые вопросы. Обязательные запреты и порядок групп применяются кодом. Модель не меняет требования и не получает права отправлять сообщения. Текст объявления рассматривается как данные, его инструкции не исполняются.

Кэш по версии требований, содержимому объявления и модели; ограничение расходов на задачу, сохранение usage. Повторная оценка только при изменении значимых данных. При сбое API — видимый статус «не оценено», без выдуманных выводов.

## Проверка магазина

Признаки для оценки: возраст и история профиля, число и содержание релевантных отзывов, реквизиты и их согласованность, возможность осмотра/самовывоза, договор, чек, гарантия, условия возврата и оплаты. Если проверки не выполнены, статус «магазин не проверен». Высокий рейтинг сам по себе не означает надёжность.

Первоначально решение «магазин допустим» подтверждает пользователь на основании показанных фактов. Позже можно согласовать формальные пороги. Ни модель, ни одно сообщение продавца не гарантируют безопасность сделки.

## Уточнения у продавцов

Пользователь разрешил уточнять детали у продавцов. Порядок — единая последовательная очередь, максимум одно исходящее сообщение одновременно. Одно первое сообщение содержит все обязательные вопросы, включая подтверждение уже написанного в объявлении. Автоматические повторные сообщения без ответа не отправлять; полученный ответ создаёт следующий шаг, если остались вопросы.

Перед каждой исходящей отправкой синхронизировать и прочитать актуальную историю выбранного диалога, включая сообщения пользователя вручную. Сначала определить, что уже спросили, на что получен ответ, какие подтверждения ещё актуальны и какие вопросы остаются открытыми. Уже заданный вопрос без ответа повторно не отправлять. Условия из объявления подтверждать в переписке; условия, уже явно подтверждённые в диалоге для текущих требований, повторно не спрашивать без причины. Повторное уточнение допустимо при устаревании ответа, изменении требований или противоречии, с указанием причины.

Черновик исходящего сообщения связывать с версией требований и последним обработанным сообщением диалога. Непосредственно перед отправкой проверять новые сообщения; если история изменилась, пересчитать открытые вопросы и обновить либо отменить черновик. Если актуальную историю получить не удалось, отложить отправку. Это правило действует для первого контакта, последующих уточнений и возобновления после перезапуска.

Правила последующего контакта при молчании и перехода к следующему продавцу ещё требуют уточнения. Отправки не должны повторяться после перезапуска или изменения ранга. Для неопределённого результата отправки — проверка истории диалога, без слепого повтора.

Уточнять точную модификацию и память; отсутствие Server Edition; физическое наличие и где находится карта; свежие фото карты и маркировки; итоговую цену; предоплату в рублях и процентах; кто финансирует закупку, доставку и дополнительные расходы; срок; проверку при получении; гарантию, документы и возврат предоплаты. Текст строится под ситуацию, без обещания покупки или оплаты.

Ответы сохраняются с источниками, при противоречиях показываются обе версии и задаётся уточнение. Условие «указано в объявлении» не отменяет вопрос продавцу. Подтверждение — на конкретную дату, с ограниченным сроком актуальности.

Перед перепиской использовать рабочую выборку 200 последних чатов для поиска известных продавцов. Новое требование пользователя — сохранить все переписки в своей БД — расширяет область хранения до всех доступных диалогов аккаунта. Поиск по старой переписке по умолчанию остаётся в рабочей выборке 200 чатов. Перед новой отправкой проверять актуальный диалог с выбранным продавцом.

## Собственная БД всех переписок

Область хранения: все доступные переписки аккаунта Авито, включая прежние диалоги, новые диалоги бота и сообщения, написанные пользователем вручную. Сохранение включает полный доступный текст входящих и исходящих сообщений, а не только выдержки, выводы DeepSeek или последние ответы. Недоступные и уже удалённые на стороне Авито сообщения восстановить обещать нельзя; пробелы и границы выгрузки показывать явно.

История связывается с аккаунтом, собеседником, диалогом, объявлениями и задачами покупки. Для сообщения сохраняются исходный ID, автор/направление, время отправки и загрузки, тип, текст, ссылки на вложения и доступные статусы. Неизвестный статус прочтения или доставки не выдумывать. Связь диалога с несколькими объявлениями и задачами допускается, без копирования одних и тех же сообщений.

Фото и документы сохранять локально в каталоге данных, в БД — метаданные, путь, контрольная сумма и результат загрузки. Одного временного URL недостаточно для архива. Неудачная или недоступная загрузка отмечается явно и может повторяться через общую очередь. Отдельно учитывать системные сообщения и иные типы вложений; неподдерживаемые типы сохранять с доступными исходными метаданными.

Модель данных: accounts, sellers, conversations, messages, message_versions, attachments, conversation_sync_state; связи с listings и purchase_tasks. Вложения хранятся вне Git, как и сама БД. Уникальность сообщения — по идентификаторам аккаунта, диалога и сообщения Авито; одинаковые тексты с разными ID остаются разными сообщениями. Сохранять наблюдаемые правки и признаки удаления, не удаляя локальную историю. Отсутствие сообщения в частично загруженной истории не означает удаление.

Первичная загрузка: импортировать уже существующие локальные снимки, включая полный архив по новому требованию хранения всех переписок, затем дозагрузить доступные сообщения из Авито с сохранением прогресса. Исходные снимки не менять. Повторный импорт не создаёт дублей. Показывать: чатов обнаружено/импортировано/проверено на полноту, сообщений сохранено, вложений загружено, незавершённых участков и ошибок. Архив — снимок на дату, а не доказательство актуальности сегодняшней переписки.

Дальнейшая синхронизация — небольшими порциями через общий регулятор Авито. Приоритет активным диалогам поиска, затем фоновому обновлению остальных. Контрольная точка синхронизации записывается после успешного сохранения порции. Перезапуск продолжает с этой точки. Дозагрузка всей истории не должна блокировать обработку новых ответов и глобальную паузу.

Ответ сначала сохраняется в БД; затем запускаются извлечение фактов и пересчёт соответствия. Факт, оценка DeepSeek, вопрос и событие совпадения ссылаются на конкретные сообщения и наблюдаемые версии. Сбой модели не теряет исходное сообщение, повторная обработка не создаёт повторных совпадений.

Исходящий текст и намерение отправки сохранять до обращения к Авито, а подтверждённый ID сообщения — после подтверждения площадкой. При неопределённом исходе проверять актуальную историю; слепой повтор запрещён. Предусмотреть просмотр истории через Telegram владельцу, поиск и выгрузку выбранного диалога. Наличие собственного архива не означает передачу всей истории в DeepSeek: наружу отправляются только минимальные обезличенные фрагменты для текущей задачи.

Локальные данные доступны только владельцу: права на БД и файлы, резервные копии с проверкой восстановления. История может содержать данные доступа из прежних покупок; их не включать в статистику, уведомления и публичные отчёты. Данные и резервные копии не публикуются на GitHub. Срок хранения и ручное удаление архива — отдельные настройки, без автоматической очистки на первом этапе.

## Нагрузка и остановка

Обязательное сетевое требование пользователя: весь трафик к Авито идёт напрямую, без VPN и прокси. Это относится к используемому Chromium, загрузке страниц, переписке, вложениям и прямым HTTP-запросам адаптеров. Отсутствие proxy-переменных или флага браузера само по себе не доказывает обход системного VPN: перед включением сбора требуется проверить фактический маршрут. Если прямой маршрут не подтверждён или изменился, действия Авито приостанавливаются. Правила маршрутизации остальных сервисов определяются отдельно; глобально отключать VPN и менять сетевые настройки без необходимости не следует.

Общая очередь всех действий с Авито: поиск, карточки, профили, диалоги. Один браузерный исполнитель, без параллельного обхода. Раздельные бюджеты на первичный сбор, обновления и переписку; кэш, контрольные точки и возобновление после перезапуска.

Предлагаемый стартовый режим: пауза 15–30 секунд между навигациями, небольшие пачки до 10 страниц с последующим перерывом; обновление выдачи раз в 30–60 минут; карточки повторно открывать по необходимости. Это проектные настройки для уменьшения нагрузки, а не лимиты, одобренные Авито, и не гарантия отсутствия блокировки.

При 429 — соблюдать Retry-After и остановить очередь на нужный срок; при 403, капче или проверке аккаунта — остановить всю активность Авито до ручного устранения. Глобальная пауза из Telegram должна прерывать ожидания и предотвращать новые действия. Прокси-ротацию, обход капчи и смену профилей не добавлять.

## Telegram и архитектура

Представление задачи: текущие требования и версия, покрытие поиска, сравнение кандидатов, причина ранга, факты и пробелы, очередь уточнений, ответы и изменение оценки. Команды/кнопки: изменить требования, обновить, показать лучшие, очередь вопросов, общая пауза, продолжить, остановить задачу. Уведомлять о новых подходящих вариантах и существенных изменениях, не о каждом повторном чтении страницы.

Отдельные обязанности по GRASP/SOLID: требования и обязательные проверки; сбор и нормализация; извлечение полей через порт модели; ранжирование; доказательства и история; очередь диалогов; единый регулятор действий Авито; Telegram-представление. Внешние механизмы — адаптеры существующих портов и новых небольших интерфейсов. Сущности задачи не должны зависеть от Telegram, CDP и DeepSeek.

## Кнопки статистики в Telegram

Все счётчики относятся к выбранной задаче, текущей версии требований и моменту последней обработки. Сводка формируется из локальной базы: нажатия кнопок не запускают обход Авито или запросы к DeepSeek. Каждый счётчик открывает соответствующий список с причинами статуса. Обновление данных — отдельное действие через общую очередь Авито.

Предлагаемое меню:

| Кнопка | Содержимое |
| --- | --- |
| Сводка | Уникальные объявления и продавцы, кандидаты по описанию, подтверждённые продавцами предложения, полные совпадения, неизвестные условия и отклонения |
| Подходят | Полные совпадения с разделением на наличие, заказ без предоплаты и заказ с допустимой предоплатой; причина и дата подтверждения |
| Лучшие варианты | Упорядоченный список по группам предпочтений; итоговая цена, срок, оплата, факты о магазине, подтверждения и оставшиеся вопросы |
| Диалоги | Продавцов в очереди, сообщений отправлено, продавцов ответили, ожидающих ответа, диалогов с неполными данными или противоречиями; просмотр сохранённой истории |
| Цена и оплата | Минимальная и медианная полная цена, величина предоплаты, срок поставки по сопоставимым подтверждённым предложениям; число вариантов без известной полной цены |
| Изменения | Новые объявления, новые полные совпадения, изменение цены/наличия/условий, утраченные совпадения, просмотр изменений за день и всё время |
| Работа бота | Текущий этап, очередь, дата последнего сбора и проверки диалогов, покрытие запросов и страниц, пауза/ошибка, число оценок и расход токенов DeepSeek; полнота архива чатов, сообщений и вложений |

«Найдено всего» означает уникальные ID объявлений, а не физическое количество карт. Число продавцов считается отдельно, объявления одного продавца связываются и не становятся дополнительными собеседниками. Одно объявление может содержать несколько модификаций: предложения различаются только при наличии данных об отдельной конфигурации и условиях, а не по предположению модели.

«Реальное предложение» для интерфейса заменяется точными статусами:

- Кандидат по описанию: модель потенциально подходит, условия ещё не подтверждены.
- Предложение подтверждено продавцом: он подтвердил, что действительно продаёт указанную карту, и обозначил наличие либо возможность заказа. Это не независимая проверка товара или магазина.
- Полностью подходит: все заданные обязательные условия подтверждены на требуемом уровне и актуальны, противоречий нет. Это полное совпадение; проверенность магазина применяется, если обязательна для данной группы.
- Нужно уточнить: нет обязательного факта, подтверждение устарело либо есть противоречие.
- Не подходит: установлен конфликт с обязательным условием, с указанием причины (Server Edition, превышение предоплаты, бюджет и т. д.).

Для основной воронки последние три статуса (полностью подходит / нужно уточнить / не подходит) взаимоисключающие. Наличие, предоплата и этап переписки — дополнительные разрезы и не должны складываться с воронкой в один итог. Недоступные/снятые объявления и непроанализированные данные выделяются отдельно, без притворного подтверждения снятия по одному отсутствию в поиске. В статистике цен учитывать только сопоставимые предложения с известной полной стоимостью и показывать размер выборки.

## Уведомление о совпадении в диалоге

После обработки каждого нового ответа продавца заново сопоставлять факты с текущими требованиями. Полное совпадение возникает, когда все обязательные условия задачи выполнены и подтверждены требуемыми источниками; высокая оценка DeepSeek сама по себе не является совпадением. Для обязательных условий, которые нужно повторно уточнить у продавца, одного текста объявления недостаточно.

При переходе предложения в полное совпадение создавать отдельное событие и доставлять уведомление в Telegram владельцу. Уведомление содержит группу приоритета (в наличии / заказ без предоплаты / заказ с допустимой предоплатой), модель и версию, полную цену, оплату, срок и место получения, гарантию и факты о магазине по заданным требованиям, короткие подтверждающие цитаты с датой, ссылки на объявление и диалог. Кнопки: открыть диалог, показать подтверждения, сравнить с лучшими, отметить просмотренным или исключить вариант. Не заявлять, что покупка согласована.

Неизвестная модификация, неуточнённая предоплата или противоречие не дают полного совпадения. Частичные совпадения доступны в статистике; отдельные уведомления о них можно добавить как настройку. Изменение требований тоже может создать полное совпадение — такое сообщение должно явно указывать причину «изменены требования», а не изображать новый ответ продавца.

Постоянный статус не рассылается при каждом опросе. Сохранять оценку, версию требований и подтверждений, событие перехода статуса и очередь уведомления одной транзакцией. Повторная обработка того же ответа и перезапуск не создают новое событие. Отметка «уведомление просмотрено» отделяется от доставки. После существенного ухудшения условий или устаревания подтверждений совпадение снимается и владелец получает уведомление с причиной; повторное подтверждение может создать событие восстановления. Незначимое редактирование требований не вызывает повторной рассылки того же результата.

Доставка повторяется при сетевом сбое. Сбой между принятием сообщения Telegram и записью подтверждения может дать дубль доставки; этого не следует путать с повторным событием совпадения. Фактическая задержка уведомления зависит от частоты проверки диалогов в общей очереди Авито, её нагрузки и состояния сайта. Проверка чатов также имеет ограниченную частоту, без постоянных запросов ради мгновенности.

## Порядок реализации и критерии приёмки

1. Карточка задачи, версии требований, обязательные исключения и перерасчёт по сохранённым данным. Server Edition не может попасть в допустимые независимо от оценки модели; неизвестная версия требует уточнения.
2. Сбор подробных карточек, группа запросов, объединение дублей и отчёт о покрытии. Пауза/возобновление без потери прогресса.
3. DeepSeek, схема ответа, цитаты, кэш и бюджет. Неизвестные факты не превращаются в подтверждённые; ошибка API видна пользователю.
4. Сравнение по группам, доказательства и проверка магазинов. Ручная сверка небольшой выборки с исходными объявлениями.
5. Собственная БД переписок: повторный импорт без дублей, сохранение исходящих и ручных сообщений, локальные вложения, контрольные точки, возобновление и восстановление резервной копии. Затем — последовательная переписка с защитой от повторов и обработкой ответов. Условия объявления подтверждаются в диалоге; уже заданные вопросы и актуальные ответы учитываются перед отправкой. Новое ручное сообщение или ответ продавца между созданием черновика и отправкой отменяет устаревший черновик. При сбое синхронизации отправки нет; неизвестный результат отправки не повторяется автоматически.
6. Статистика и кнопки Telegram из локальных данных: единые определения, переходы к спискам, исключение дублей, дата актуальности и отсутствие запросов Авито при нажатии кнопки.
7. События совпадений по ответам: неизвестные обязательные условия запрещают совпадение, повторный ответ/перезапуск не создаёт событие повторно, ухудшение условий снимает совпадение, недоставка сохраняется для повторной попытки.
8. Интеграционный прогон на этой видеокарте: собрать доступную выборку, проверить исключения, выбрать кандидатов, уточнить условия, показать подтверждённый список. Выпускать этапами с тестами и коммитами, без публикации переписки и ключей.

До реализации уточнить: 96 ГБ и допустимость Max-Q; бюджет/город/состояние/срок/предоплата; область требования проверенного магазина; смысл «одно сообщение за раз» при молчании продавца.
