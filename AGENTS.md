# Работа в проекте Авито

- Перед работой прочитать `README.md`: там точный браузер и профиль с авторизацией.
- Браузер: `/snap/bin/chromium`, профиль `/home/mg/kinobot/chrome-profile`, CDP `127.0.0.1:9222`. Сначала использовать работающий экземпляр. Не подменять его обычным Google Chrome или другим профилем.
- Весь трафик Авито должен идти напрямую, без VPN и прокси, включая Chromium и HTTP-адаптеры. Проверять фактический маршрут; отсутствие proxy-переменных не исключает системный VPN.
- `/home/mg/kinobot` — отдельный проект. Проект Авито расположен в `/home/mg/projects/avito`; не смешивать их. Путь к профилю Chromium сам по себе не означает принадлежность кода этому проекту.
- Для поиска сначала использовать `avito-export-200/all-chats.json`: пользователь ограничил рабочую выборку 200 самыми свежими чатами. Полная выгрузка лежит отдельно; расширять поиск на неё по запросу пользователя.
- Пользователь просит избегать повторяющихся разрешений на отдельные шаги. Для длительной выгрузки подготовить один понятный скрипт и запускать работу целиком. Обязательные ограничения среды и запросы разрешений соблюдать; не обещать их отсутствие.
- Пользователь уже разрешил чтение и локальную выгрузку своей переписки. Отправку сообщений собеседникам выполнять только по явному поручению.
- Не выводить пароли и коды доступа в отчёты о поиске, когда достаточно даты, продавца и деталей покупки.
- Не коммитить и не публиковать выгрузки, ZIP-архивы, cookies и профиль браузера. Профиль браузера не копировать в проект.
- Текущие снимки сохранять. Обычный запуск `export_avito.py` при наличии отчёта выполняет проверку и упаковку, а не новую синхронизацию.

## Разработка Rust-бота

- Придерживаться GRASP и SOLID; границы модулей описаны в `docs/architecture.md`.
- Сценарии зависят от портов `ListingSource` и `ListingRepository`. CDP, разметку Авито, SQLite и HTML держать в адаптерах.
- Условия покупки хранятся как версии задачи; естественный язык преобразуется DeepSeek в черновик, обязательные правила применяет код. Состояние реализации — в `docs/implementation-status.md`.
- Ошибка браузера, капча или неизвестная разметка не должны превращаться в успешный пустой проход.
- Перед коммитом выполнять `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`.
- Браузерную фикстуру запускать отдельно: `cargo test --locked -- --ignored`; использовать только указанный выше Chromium.
- Пользователь разрешил создание репозитория GitHub и push законченных изменений. Репозиторий `dftpnd/avito-browser-bot` пользователь явно поручил сделать публичным. Авторизация должна быть доступна; отсутствие доступа не обходить.
- Публиковать только исходники, тестовые фикстуры и документацию проекта. `README.local.md`, выгрузки переписки, результаты мониторинга, cookies и профиль остаются локально.

## Telegram

- Токен и ID владельца хранить только в `config.local.json` с правами 600, файл не публиковать.
- Перед запуском Telegram-режима проверить владельца по его личному `/start` и подтверждению пользователя. Не назначать владельцем произвольного первого собеседника.
- Команды управления доступны только проверенному владельцу в личном чате. События объявлений доставлять этому владельцу по его командам сканирования/мониторинга.
- Сценарий Telegram зависит от портов `BotTransport` и `BotRepository`, сетевой API изолирован в адаптере.
